# PHP Runtime Audit

A local-first PHP runtime security audit and patch-verification project. The initial focus is PHP2Shell; the product is intended to support versioned PHP advisories over time.

> **Status:** Repository bootstrap. No production audit or "safe" verdict is available yet.

## Bootstrap the governed development workflow

Requires PHP 8.3+ and Composer on the development host. Audit targets may use older PHP versions; development-runtime requirements do not establish target patch status.

The Composer lockfile and canonical Codex projection generated by the locked `voku/agent-loop` dependency are committed: `AGENTS.md`, `.agent-loop/`, `.codex/agents/`, `.codex/skills/` and `.codex/rules/`. Install and inspect the workflow with:

```bash
composer install --no-interaction --prefer-dist --no-progress
vendor/bin/agent-loop init doctor
vendor/bin/agent-loop init sync-policy --agent=codex
vendor/bin/agent-loop init host-status --agent=codex --format=json
```

Review the current projection before changing it:

```bash
vendor/bin/agent-loop init install-assets --agent=codex --dry-run
```

Do not hand-copy generated assets. For governed work, use `vendor/bin/agent-loop enter <task-id> --format=json`, follow the returned `next_action_kind` and `next_action`, and end with `finish`. No invented task approvals or closeout. See [the official quick start](https://github.com/voku/agent-loop/blob/main/docs/quick-start.md).

## Product intent

- Audit local PHP runtimes, SAPI/process identity, distro backports, extensions and relevant configuration.
- Distinguish **patched**, **potentially affected**, **unverified** and **investigation required** from independently observed indicators of compromise.
- Generate read-only, locally executable checks, machine-readable evidence, and proposed remediation for a human or coding agent to review.
- No URL-driven active exploitation, no intrusive production tests, no upload of private server data by default.

See [the implementation plan](docs/IMPLEMENTATION_PLAN.md) for deliverables and gates.

## Validate local evidence records

PRA-3 adds versioned evidence records for observations, applicability, assessments, coverage and findings. The validator checks one caller-supplied local JSON file against the bundled v1 schema, applies typed-model consistency checks, and writes a structured result to standard output:

```bash
php bin/php-runtime-audit-evidence validate tests/fixtures/evidence/v1/observation.valid.json
```

The command accepts only a local file path, rejects URL and UNC paths, reads at most 1 MiB, rejects duplicate JSON object keys, and does not resolve source locators contained in the record. Source freshness is derived only from the captured and current SHA-256 digests already present in the JSON. Missing digest evidence remains `unknown`. An assessment keeps patch status separate from compromise evidence. `verified_fixed` and `potentially_affected` patch statuses require evidence IDs; `none_observed` means no compromise was observed in the supplied evidence and does not mean the host was never compromised.

Schema version `1.0` is stored under `resources/schemas/evidence/v1/`. Unknown record types and schema versions fail closed. The validator does not collect runtime facts, decide vendor backports, or establish whether a host is safe.

## Security

Never treat `php -v`, response headers or HTTP success as proof of a patched web-facing runtime. No shell pipelines from remote user input. Treat generated instructions and collected logs as untrusted data. Never store SSH credentials in the website.
